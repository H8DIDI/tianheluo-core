# 出图插件重构方案（草案，待确认）

> 目的：减少出图插件之间的重复，统一图例、图框、编号和注释族，解决市政大范围图纸无法在 A0 上清晰出图的问题。
> 本文只做分析和方案，**未改动任何代码或模型**。

## 一、模型实况（只读统计，2026-10-13）

| 项目 | 数量 | 说明 |
|---|---|---|
| 图纸 | 69 张 | 其中“井大样_”48 张，其它 21 张（命名不统一） |
| 视图（非样板） | 1235 个 | 大量是生成遗留的 `平面_AG-*`、`南/北/东/西_AG-*` 等，需要清理 |
| 视图样板 | 28 个 | 名字和用途不统一（如 `11KV`、`LV`、`TELCO`、`AAA井大样出图视图`） |
| 图框类型 | 12 种 | 没有按图纸类型区分 |
| 文字类型 | 19 种 | 字高、字体不统一 |
| 标记族类型 | 29 种（7 个类别） | 结构框架、楼板、常规模型、线管、管道、立面、注释记号等分散 |
| 通用注释族 | 0 种 | 注释全靠标记族和文字类型 |

**关键结论**：标注问题的根源不是插件少或多，而是**没有一套“构件类别 → 标记族”的标准映射**。插件只是把错误的映射执行得更快。

## 二、现有出图插件盘点与交叉

| 插件 | 作用 | 与其它插件的交叉 |
|---|---|---|
| 图纸管理（sheet-manager，pyRevit） | 图号/图名表格、批量建图、复制、删除、修订、图纸集、导出 PDF/CSV | 查找替换与“视图管理”完全重复；导出与“图纸签发”重复；批量建图与“批量生成平面图”都在建图 |
| 视图管理（view-manager，pyRevit） | 视图重命名、套样板、比例/详细程度/专业、查找替换、删除未上图视图 | 查找替换重复；套样板与“批量生成平面图”、“一键井展开图”各写了一套 |
| 图纸签发管理（issue-manager，pyRevit） | 签发 PDF/DWG、签发记录、明细表 | 导出 PDF 与“图纸管理”“一键井展开图”的导出重复 |
| 批量生成平面图（plan-batch，C#） | 视图类型 × 标高 批量建平面视图 | 与“一键井展开图”的视图创建、与“视图管理”的样板功能重叠 |
| 一键井展开图（well-sheets，Python） | 每口井：平面 + 四面剖面 + 套图框，批量 1:50 | 自己创建视图、套样板、导出 PDF，和上面几个都有重叠；标注已拆出 |
| 一键井大样标注（well-annotate，实验） | 按可见构件外包框标注 | 与“排管标注”、井展开图的标注职责重叠，都在“加标注” |
| 一键排管标注（duct-annotate，实验） | 给每根排管标注 | 同上 |
| 一键导出井大样 DWG / 一键导出 NWC（export-dwg / export-nwc） | 导出 | 与“图纸签发”“图纸管理”的导出重复 |
| 一键清除井标记 / 一键编号 / 井深调整 / 明细表 Excel 互导 / 强电井清洗合并 | 井数据处理 | 与出图关系不大，但“编号”和“图纸编号”规则需要统一 |

**重复最严重的 5 处**：
1. **查找替换**：图纸管理、视图管理各一份。
2. **导出 PDF / DWG**：图纸管理、图纸签发、井展开图、导出 DWG 四处。
3. **建视图 / 套样板**：批量生成平面图、井展开图、视图管理三处。
4. **加标注**：井大样标注、排管标注、井展开图的标注预处理三处，且两个标注插件都是实验功能。
5. **编号**：图纸管理的批量改号、井展开图的图号、一键编号的井号，三套规则。

## 三、对你痛点的对应

| 痛点 | 现状 | 方案 |
|---|---|---|
| 1. 报审图纸要统一图例 | 图例靠人工，视图样板各自为政 | 建立**图例与样板标准表**（一个文件）：每种图纸类型（平面/剖面/详图）对应唯一样板，样板只允许从标准表里选 |
| 2. 套图框和编号 | 图框 12 种，编号三套规则 | 建立**图纸编号规则**（如 `专业-类型-序号`），一个“编排”命令负责：选图框、按规则编号、建图纸 |
| 3. 注释族太多，参数乱，漏标/错标 | 29 种标记族，没有标准 | 建立**标注标准表**：构件类别 → 标准标记族 → 必需参数。提供**只读检查**（列出漏标、用错的构件）；确认后再做“一键按标准补标/替换” |
| 4. 市政范围大，1:2000 放不进 A0，文字乱 | 目前只能缩小比例 | **分区布图**（CAD 视口式）：把大范围按固定网格切成若干块，每块一个平面视图（统一比例，如 1:500），每块一张或多张图纸，图纸之间用“分区号”对应总图 |
| 5. 特殊图（埋深范围图、做法剖面） | 目前靠手动 | 保留手动为主；提供“剖面快速生成”（按选定两点生成剖面）作为后续功能，不放进第一期 |

## 四、建议的新结构（从 10 个出图插件收敛为 4 个）

1. **图纸编排**（合并：图纸管理 + 批量生成平面图 + 视图管理中的建视图/套样板部分）
   - 图纸编号规则、图框选择、批量建图、分区布图、视图批量生成、样板套用（只用标准表里的样板）。
   - 查找替换只保留一份。
2. **出图导出**（合并：图纸签发 + 导出井大样 DWG + 导出 NWC + 图纸管理的 PDF 导出）
   - 统一导出入口：PDF、DWG、NWC、签发记录。一套导出设置。
3. **标注中心**（合并：一键井大样标注 + 一键排管标注 + 井展开图的标注部分）
   - 标注标准表、只读检查（漏标/错标清单）、一键按标准补标。
   - 两个实验标注插件暂停，先做检查，再做补标。
4. **井展开图**（保留：一键井展开图，去掉自己的建视图和导出，改为调用 1、2、3）

井数据类（井深调整、一键编号、清除井标记、明细表互导、强电井清洗合并）保持独立，不改动。

**视图清理**（一次性）：把 1235 个视图里的遗留 `*_AG-*` 视图列成清单，用户确认后批量清理。

## 五、分期计划

- **第 0 期（先做，不改模型）**：标注标准表草案 + 只读检查（漏标/错标清单）+ 视图/图纸遗留清单。需要你确认标准表（见下）。
- **第 1 期**：图纸编排（编号规则、图框、分区布图）。把“查找替换”合并为一份。
- **第 2 期**：出图导出统一入口；图纸签发并入。
- **第 3 期**：标注中心的补标功能；井展开图改为调用 1、2、3；删除旧的重复插件（保留旧版本可下载，不破坏已装用户）。

## 六、需要你确认的事项

1. **图纸编号规则**：例如 `专业-类型-序号`，比如 `市政-总图-01`、`井大样-A-029`？还是沿用现在的 `井大样_A-29`？
2. **分区布图**：A0 图框下用多大的比例？（比如 1:500，分区大小 X 米 × Y 米），是否需要分区编号和总图索引？
3. **标注标准表**：29 种标记族里，每类构件用哪一种为标准？我可以先列出每个类别现有的标记族，你来指定（或让我按名称猜，你再改）。
4. **Sendit 的 pyRevit 插件**（图纸管理、视图管理、图纸签发）：是保留 Python 版，还是用 C# 重写？重写更稳定、可统一风格，但工作量大。
5. **两个实验标注插件**：先停用，等第 3 期统一重做，可以吗？
6. **遗留视图和图纸**：清理前是否需要备份，或者哪些命名前缀可以确定删除？

## 七、风险

- 1235 个视图中可能有人在用的手工视图，清理前必须逐个确认，不能按前缀直接删。
- 已经签发、报审的图纸不要改编号，新规则只用于新图。
- 旧插件下线要保留一段过渡期，已装用户的工作流不能突然失效。
